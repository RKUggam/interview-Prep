1. HTTP/REST Basics, FastAPI Fundamentals & Architecture

What is an API? What is a REST API?

An API (Application Programming Interface) is a contract that lets one program use another program's functionality or data. A web API exposes it over HTTP. REST (Representational State Transfer) is an architectural style for web APIs with these principles:

  • Resources are identified by URLs (/users/42), and you act on them with HTTP methods.
  • Each request is stateless: it carries everything needed, such as an auth token, and the server keeps no client session between requests.
  • A client-server split, a uniform interface, cacheable responses and a layered system (proxies and gateways in between).
  • Representations are usually JSON.

Good REST design uses nouns in plural (/orders, not /getOrders), nests sub-resources (/users/42/orders), uses proper status codes, and adds versioning, filtering, pagination and consistent error bodies.

What does an HTTP request and response consist of?

Request:

  • The method (GET, POST, ...)
  • The URL: scheme, host, port, path and query string, e.g., /items/5?details=true
  • Headers (Content-Type, Authorization, Accept, cookies)
  • An optional body (JSON, form data, files)

Response:

  • A status code and reason phrase (200 OK)
  • Headers (Content-Type, Set-Cookie, Cache-Control)
  • An optional body

In FastAPI, these parts map to path/query/header/cookie/body parameters and to Response objects.

What do the HTTP status code classes mean? Name the codes you use most.

  • 1xx Informational (101 Switching Protocols for WebSockets)
  • 2xx Success: 200 OK, 201 Created, 202 Accepted (async job), 204 No Content
  • 3xx Redirection: 301/308 permanent, 302/307 temporary, 304 Not Modified (cache)
  • 4xx Client error: 400, 401, 403, 404, 405 Method Not Allowed, 409, 413 Payload Too Large, 415 Unsupported Media Type, 422, 429
  • 5xx Server error: 500, 502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout

FastAPI provides named constants such as status.HTTP_201_CREATED.

What is the difference between REST, GraphQL, gRPC and WebSockets?

REST: resource URLs plus HTTP verbs; simple and cacheable, but can over-fetch or under-fetch data. GraphQL: a single endpoint where the client specifies exactly which fields it wants; flexible for frontends, but caching is harder and N+1 queries are a risk. In Python, Strawberry integrates with FastAPI via GraphQLRouter. gRPC: binary Protobuf over HTTP/2 with strongly typed contracts and streaming; fast for service-to-service calls, but not browser-native. WebSockets: persistent bidirectional real-time channel.

How do you install FastAPI and what does fastapi[standard] include?

Run pip install "fastapi[standard]" inside a virtual environment (python -m venv .venv, or uv venv). The standard extra adds:

Plain pip install fastapi installs only the core: Starlette and Pydantic.

What is a "path operation" and a "path operation function"?

In FastAPI terminology, a path is the URL route (/items/{id}) and an operation is the HTTP method. A path operation decorator (@app.get("/items/{id}")) binds them to a path operation function: the Python function that handles the request. The function's return value (dict, list, Pydantic model, str, int, None, ORM object) is automatically converted to JSON.

What is the difference between OpenAPI, Swagger and JSON Schema?

OpenAPI is the specification: a machine-readable description of an API's endpoints, parameters, schemas and auth, formerly called the Swagger Specification. Swagger UI is a tool that renders an OpenAPI document as interactive docs where you can try requests. JSON Schema describes the shape of JSON data; OpenAPI uses it for request and response bodies, which FastAPI generates from Pydantic models.

What is FastAPI and what are its key features?

FastAPI is a modern, high-performance Python web framework for building APIs, based on standard Python type hints. Key features:

  • Fast: built on Starlette (ASGI) and Pydantic; performance comparable to Node.js/Go frameworks.
  • Type-hint driven: request parsing, validation, serialization and docs derived from annotations.
  • Automatic interactive docs: OpenAPI schema, Swagger UI (/docs) and ReDoc (/redoc).
  • Dependency injection system that is simple yet powerful.
  • Native async support (async def) plus sync endpoints run in a threadpool.
  • Standards-based: OpenAPI, JSON Schema, OAuth2, JWT.
  • Excellent editor support (autocomplete, type checks), fewer bugs.

What are Starlette and Pydantic, and what role does each play in FastAPI?

Starlette is a lightweight ASGI toolkit that provides the web layer: routing, requests/responses, middleware, WebSockets, background tasks, test client, static files. FastAPI subclasses Starlette. Pydantic provides the data layer: parsing, validation, serialization and JSON Schema generation from type-annotated models. FastAPI glues them together and adds dependency injection and OpenAPI generation.

What is ASGI and how does it differ from WSGI?

WSGI (Web Server Gateway Interface) is a synchronous standard: one request occupies one worker thread/process until done; no native WebSockets or long-lived connections (Flask, Django classic). ASGI (Asynchronous Server Gateway Interface) is its async successor: an app is an async callable app(scope, receive, send); it supports HTTP, HTTP/2, WebSockets, lifespan events, and many concurrent connections on a single event loop. FastAPI is an ASGI app served by ASGI servers like Uvicorn, Hypercorn or Granian.

What is Uvicorn? How do Uvicorn and Gunicorn relate?

Uvicorn is a lightning-fast ASGI server built on uvloop and httptools. Gunicorn is a mature process manager (WSGI server). In production you can run Gunicorn with Uvicorn workers (gunicorn -k uvicorn.workers.UvicornWorker -w 4 app:app) to get multiple processes with supervision, or simply use uvicorn app:app --workers 4 (or fastapi run). In Kubernetes, one Uvicorn process per container with replicas is often preferred.

How does FastAPI generate API documentation automatically?

At startup FastAPI inspects every route: path, method, parameter annotations, Pydantic models for body/response, status codes, dependencies, security schemes, tags and docstrings. It builds an OpenAPI 3.1 schema (served at /openapi.json) using Pydantic's JSON Schema generation. Swagger UI (/docs) and ReDoc (/redoc) render that schema. You can customize with title, description, tags, summary, response_description, openapi_url=None (disable), or override app.openapi().

What happens internally when a request hits a FastAPI endpoint?

  1. ASGI server (Uvicorn) parses the HTTP request and calls the app with scope/receive/send.
  2. Middleware stack runs (outermost first): e.g., CORS, GZip, custom middleware.
  3. Starlette router matches path + method to a route.
  4. FastAPI resolves the dependency graph: extracts path/query/header/cookie/body params, runs dependencies (cached per request), validates with Pydantic.
  5. On validation failure → RequestValidationError → 422 response.
  6. Endpoint runs (awaited if async def, else in a threadpool).
  7. Return value is filtered/validated against response_model, serialized via jsonable_encoder/Pydantic to JSON, wrapped in a Response.
  8. Dependencies with yield run their teardown; background tasks run after the response is sent.

What are type hints and why are they central to FastAPI?

Type hints (PEP 484) annotate expected types: def f(x: int) -> str. Python ignores them at runtime, but FastAPI reads them via introspection to decide where a parameter comes from (path/query/body), how to convert it (string → int), how to validate it, and how to document it. Annotated[T, metadata] (PEP 593) lets you attach extra info like Query(max_length=50) or Depends(...) while keeping the real type.

What is the FastAPI CLI?

Installed with pip install "fastapi[standard]". fastapi dev main.py runs Uvicorn with auto-reload on localhost for development; fastapi run main.py runs in production mode (listening on 0.0.0.0, no reload). It auto-detects the app object.

2. Routing, Path, Query, Header & Body Parameters

How does FastAPI decide whether a function parameter is a path, query or body parameter?

  • If the name appears in the path template (/items/{item_id}) → path parameter.
  • If it is a singular type (int, str, float, bool, Enum, UUID, datetime, list of these with Query) → query parameter.
  • If it is a Pydantic model (or declared with Body()) → request body.
  • Explicit markers override: Path(), Query(), Header(), Cookie(), Body(), Form(), File().

How do you make query parameters optional, required, or with defaults? How do you add validation?

from typing import Annotated
from fastapi import Query

@app.get("/search")
async def search(
    q: Annotated[str, Query(min_length=3, max_length=50, pattern="^[a-z]+$")],  # required
    page: int = 1,                          # optional with default
    tag: str | None = None,                 # optional, may be None
    ids: Annotated[list[int], Query()] = [],  # ?ids=1&ids=2
):
    ...

A parameter with no default is required. Query supports alias, title, description, deprecated, include_in_schema, numeric constraints (gt, ge, lt, le).

Why does route declaration order matter?

Routes are matched in the order they are declared. If /users/{user_id} is declared before /users/me, the request /users/me matches the first route and tries to parse "me" as user_id. Declare fixed paths before parameterized ones.

How do you restrict a path parameter to a set of predefined values?

from enum import Enum
class ModelName(str, Enum):
    resnet = "resnet"
    vit = "vit"

@app.get("/models/{name}")
async def get_model(name: ModelName):
    return {"model": name.value}

Alternatively use Literal["resnet", "vit"]. Invalid values give a 422 and the options appear in docs.

How do you capture a path containing slashes (e.g., a file path)?

Use the Starlette path convertor: @app.get("/files/{file_path:path}"). Other convertors: int, float, uuid, str.

How do you read headers and cookies?

from fastapi import Header, Cookie
@app.get("/info")
async def info(user_agent: Annotated[str | None, Header()] = None,
               x_token: Annotated[list[str] | None, Header()] = None,
               session_id: Annotated[str | None, Cookie()] = None):
    ...

Header converts underscores to hyphens automatically (user_agent → User-Agent); headers are case-insensitive. Disable with convert_underscores=False.

How do you accept multiple body parameters or a singular value in the body?

@app.put("/items/{item_id}")
async def update(item_id: int, item: Item, user: User,
                 importance: Annotated[int, Body(gt=0)]):
    ...

With multiple body params, FastAPI expects a JSON object keyed by parameter names: {"item": {...}, "user": {...}, "importance": 5}. For a single model, use Body(embed=True) to require {"item": {...}} instead of the bare object.

Can you use Pydantic models for query parameters?

Yes (FastAPI ≥ 0.115): filters: Annotated[FilterParams, Query()] where FilterParams is a BaseModel. Set model_config = {"extra": "forbid"} to reject unknown query params. Same works for Header() and Cookie().

What HTTP methods does FastAPI support and when do you use each?

@app.get (read), post (create / non-idempotent actions), put (full replace, idempotent), patch (partial update), delete (remove), plus options, head, trace. Use @app.api_route(path, methods=[...]) for multiple. For PATCH, use item.model_dump(exclude_unset=True) to update only provided fields.

How do you access the raw Request object?

Declare a parameter of type Request: async def f(request: Request). Gives access to request.headers, request.client.host, request.url, await request.body(), await request.json(), request.state, request.app. Data read this way bypasses validation and docs.

When should you use a path parameter vs a query parameter vs the request body?

  • Path: identifies a specific resource, and is required (/users/42).
  • Query: optional modifiers such as filtering, sorting, pagination and search (/users?role=admin&page=2).
  • Body: data being created or updated, or complex or large input, sent with POST/PUT/PATCH. Avoid bodies on GET.
  • Headers: metadata such as auth, content negotiation and correlation IDs.

How does FastAPI convert query parameter types, e.g., booleans?

Query values arrive as strings, and Pydantic converts them to the annotated type. For bool, the values 1, true, on and yes (case-insensitive) become True, and 0, false, off and no become False. Invalid values such as ?page=abc for an int produce a 422 error listing the location (["query", "page"]) and the message.

What does a 422 validation error response look like?

{"detail": [{"type": "int_parsing", "loc": ["path", "item_id"],
             "msg": "Input should be a valid integer, unable to parse string as an integer",
             "input": "abc"}]}

loc shows where the error is (path, query, body field path); type is a machine-readable error code. You can customize the format with a RequestValidationError handler.

3. Pydantic Models & Data Validation

What is Pydantic and how is it used in FastAPI?

Pydantic is a data validation library that uses type hints to parse and validate data; v2 has a Rust core (pydantic-core) and is 5–50x faster than v1. In FastAPI, BaseModel subclasses define request bodies, response models, query/header models and settings. Invalid input raises ValidationError, which FastAPI turns into a 422 response with detailed error locations.

from pydantic import BaseModel, Field, EmailStr
class UserCreate(BaseModel):
    username: str = Field(min_length=3, max_length=30)
    email: EmailStr
    age: int = Field(ge=0, le=130)
    tags: list[str] = []

How do you write custom validators in Pydantic v2?

from pydantic import BaseModel, field_validator, model_validator

class SignUp(BaseModel):
    password: str
    confirm: str

    @field_validator("password")
    @classmethod
    def strong(cls, v: str) -> str:
        if len(v) < 8 or v.isalpha():
            raise ValueError("weak password")
        return v

    @model_validator(mode="after")
    def match(self):
        if self.password != self.confirm:
            raise ValueError("passwords do not match")
        return self

mode="before" runs before type coercion (raw input); "after" on validated data; "wrap" wraps the inner validator. Also Annotated[str, AfterValidator(fn)] for reusable validators.

What is Field() used for?

To add constraints and metadata to model fields: default, default_factory, alias, title, description, examples, gt/ge/lt/le, min_length/max_length, pattern, multiple_of, frozen, exclude. Use default_factory=list for mutable defaults (though Pydantic copies defaults safely anyway).

Why use separate input and output models (e.g., UserCreate, UserRead, UserInDB)?

To avoid leaking sensitive fields (password hash), to control what clients can set (no id/created_at on input), and to document each contract precisely. Common pattern: UserBase (shared fields) → UserCreate(UserBase) adds password; UserRead(UserBase) adds id; UserInDB adds hashed_password. Use UserUpdate with all-optional fields for PATCH.

What does response_model do?

It declares the output schema. FastAPI will: validate the return value, filter out fields not in the model (security), serialize it, and document it in OpenAPI. You may also use the return type annotation (-> UserRead). Options: response_model_exclude_unset=True, response_model_exclude_none, response_model_include/exclude. Set response_model=None to disable when returning a Response directly.

How do you return ORM objects through Pydantic models?

Set model_config = ConfigDict(from_attributes=True) on the response model (v1: orm_mode = True). Pydantic will read attributes (obj.name) instead of dict keys, so you can return a SQLAlchemy instance and FastAPI converts it via UserRead.model_validate(db_user).

How do you handle nested models, lists and unions?

class Image(BaseModel):
    url: HttpUrl
    name: str
class Item(BaseModel):
    name: str
    images: list[Image] | None = None
    meta: dict[str, int] = {}
class Cat(BaseModel): kind: Literal["cat"]; meows: int
class Dog(BaseModel): kind: Literal["dog"]; barks: int
Pet = Annotated[Cat | Dog, Field(discriminator="kind")]

Discriminated unions validate faster and produce clearer errors than plain unions.

What is strict mode vs lax mode in Pydantic?

By default (lax) Pydantic coerces compatible types: "42" → 42, "true" → True. Strict mode (ConfigDict(strict=True), Field(strict=True), or StrictInt) rejects mismatched types. Useful for financial or security-sensitive inputs.

What are computed fields, aliases and extra config?

  • @computed_field + @property: derived value included in serialization and schema.
  • Field(alias="userName"): external name differs from attribute; populate_by_name=True accepts both; alias_generator=to_camel for camelCase APIs; serialization_alias / validation_alias to differ by direction.
  • extra="ignore" (default) / "forbid" (reject unknown fields) / "allow" (keep them).

What is jsonable_encoder?

A FastAPI utility that converts arbitrary objects (Pydantic models, datetime, UUID, Decimal, sets, ORM objects) into JSON-compatible Python types (dict, list, str, ...). Useful when storing to a NoSQL DB or building a JSONResponse manually.

What is TypeAdapter?

A Pydantic v2 tool to validate/serialize arbitrary types that are not BaseModels, e.g. TypeAdapter(list[Item]).validate_python(data) or .json_schema().

4. Responses, Status Codes & Error Handling

How do you set custom status codes?

Via the decorator: @app.post("/items", status_code=status.HTTP_201_CREATED). For dynamic codes, inject response: Response and set response.status_code = 202, or return a JSONResponse(content=..., status_code=...). Use 204 with no body for deletes.

What response classes are available?

  • JSONResponse (default), ORJSONResponse / UJSONResponse (faster JSON).
  • HTMLResponse, PlainTextResponse, RedirectResponse.
  • StreamingResponse (generator/async generator), FileResponse (efficient file sending with headers).
  • Generic Response(content, media_type, headers).

Set app-wide default: FastAPI(default_response_class=ORJSONResponse). Returning a Response directly skips response_model validation.

How do you raise HTTP errors?

from fastapi import HTTPException
@app.get("/items/{id}")
async def get(id: int):
    item = db.get(id)
    if not item:
        raise HTTPException(status_code=404, detail="Item not found",
                            headers={"X-Error": "missing"})
    return item

Raising (not returning) aborts the dependency chain and endpoint immediately; detail can be any JSON-serializable value.

How do you implement custom exception handlers?

class DomainError(Exception):
    def __init__(self, msg: str): self.msg = msg

@app.exception_handler(DomainError)
async def domain_handler(request: Request, exc: DomainError):
    return JSONResponse(status_code=400, content={"error": exc.msg})

@app.exception_handler(RequestValidationError)
async def validation_handler(request, exc):
    return JSONResponse(status_code=422, content={"errors": exc.errors()})

You can also override Starlette's HTTPException handler to unify the error format. Re-use defaults via fastapi.exception_handlers.http_exception_handler.

What is the difference between 400, 401, 403, 404, 409, 422 and 500?

400 Bad Request (malformed / business-rule violation); 401 Unauthorized (missing/invalid credentials — include WWW-Authenticate); 403 Forbidden (authenticated but not allowed); 404 Not Found; 409 Conflict (duplicate resource / version conflict); 422 Unprocessable Entity (FastAPI's validation errors); 429 Too Many Requests; 500 Internal Server Error (unhandled exception); 503 Service Unavailable (dependency down / overloaded).

How do you document multiple possible responses?

@app.get("/items/{id}", response_model=Item,
         responses={404: {"model": ErrorMsg, "description": "Not found"},
                    200: {"content": {"image/png": {}}}})

How do you set headers and cookies on a response?

Inject response: Response and call response.headers["X-Cache"] = "HIT" or response.set_cookie("session", token, httponly=True, secure=True, samesite="lax"); or set them on a returned JSONResponse.

5. Dependency Injection

What is dependency injection in FastAPI and why is it useful?

A dependency is any callable (function, class, async function, generator) declared via Depends(). FastAPI calls it, resolving its own parameters (path, query, other dependencies) recursively, and injects the result. Benefits: code reuse (pagination, auth, DB session), separation of concerns, easy testing via overrides, automatic documentation of the dependency's parameters, and resource lifecycle management with yield.

async def pagination(skip: int = 0, limit: int = Query(10, le=100)):
    return {"skip": skip, "limit": limit}
Pagination = Annotated[dict, Depends(pagination)]

@app.get("/items")
async def items(p: Pagination): ...

Explain dependencies with yield.

Code before yield is setup; the yielded value is injected; code after yield runs as teardown after the response is produced (similar to a context manager). Typical for DB sessions:

def get_db():
    db = SessionLocal()
    try:
        yield db
        db.commit()
    except Exception:
        db.rollback()
        raise
    finally:
        db.close()

Since FastAPI 0.106, exit code runs before the response is sent (so you cannot use the resource in background tasks; create a new session there). Exceptions raised in the endpoint propagate into the dependency's except block.

What are sub-dependencies and dependency caching?

Dependencies can depend on other dependencies, forming a DAG. Within a single request, if the same dependency is used multiple times, it is executed once and the result cached. Disable with Depends(dep, use_cache=False).

How do you use classes as dependencies?

Any callable works; a class's __init__ parameters become request parameters: commons: Annotated[CommonParams, Depends()] (shortcut: empty Depends() uses the annotated type). A callable instance (class with __call__) allows parameterized dependencies, e.g., Depends(RoleChecker(["admin"])).

How do you apply dependencies to a whole router or app without using their return values?

@app.get("/x", dependencies=[Depends(verify_key)]), APIRouter(dependencies=[Depends(get_current_user)]), or FastAPI(dependencies=[Depends(log_request)]). Useful for auth checks, rate limiting, logging.

How do you override dependencies in tests?

def fake_user(): return User(id=1, name="test")
app.dependency_overrides[get_current_user] = fake_user
# ... run tests ...
app.dependency_overrides.clear()

What is Security() vs Depends()?

Security is a subclass of Depends that additionally accepts scopes=[...]. Scopes are collected into SecurityScopes for OAuth2 scope-based authorization and documented in OpenAPI.

Should dependencies be sync or async?

Either; FastAPI awaits async ones and runs sync ones in the threadpool. Make it async if it awaits I/O (async DB, HTTP client); keep it sync if it does blocking I/O or is trivial CPU work. Mixing is fine.

6. Async, Concurrency & Performance

What are coroutines, the event loop and async/await?

An async def function returns a coroutine object when called; it doesn't run until awaited or scheduled. await suspends the coroutine until the awaited operation (e.g., a network response) finishes, which gives control back to the event loop. The event loop is a single-threaded scheduler that runs whichever task is ready. While one request waits on the database, the loop serves other requests, so one process can handle thousands of concurrent I/O-bound connections.

async def fetch_user(id):
    await asyncio.sleep(1)        # non-blocking: other tasks run meanwhile
    return {"id": id}

async def main():
    users = await asyncio.gather(*(fetch_user(i) for i in range(100)))  # ~1 s, not 100 s

You can only await inside async def. Forgetting await returns an un-run coroutine (Python warns: "coroutine was never awaited").

When should you use async def vs def for path operations?

  • async def: when calling libraries that support await (httpx.AsyncClient, asyncpg, SQLAlchemy async, aioredis, motor). Runs directly on the event loop.
  • def: when using blocking libraries (requests, psycopg2, sync SQLAlchemy, file I/O, most ML inference). FastAPI runs it in an external threadpool (AnyIO, default 40 threads) so it does not block the loop.
  • Never perform blocking calls (time.sleep, requests.get, heavy CPU) inside async def — this freezes the whole event loop and all concurrent requests.

Explain concurrency vs parallelism in the context of FastAPI.

Concurrency: many tasks make progress by interleaving while waiting on I/O (event loop, async/await, single thread). Parallelism: tasks run simultaneously on multiple CPU cores (multiple processes). FastAPI achieves concurrency with asyncio and threads; for CPU parallelism, run multiple worker processes (Uvicorn/Gunicorn workers) or offload to a process pool / task queue, because of Python's GIL.

How do you run CPU-bound or blocking code from an async endpoint?

from fastapi.concurrency import run_in_threadpool
result = await run_in_threadpool(blocking_fn, arg)          # I/O-bound blocking

loop = asyncio.get_running_loop()
result = await loop.run_in_executor(process_pool, cpu_fn, x)  # CPU-bound

What techniques improve FastAPI performance?

  • Use async drivers end-to-end; avoid blocking the loop.
  • Multiple workers / replicas; tune threadpool size for sync endpoints.
  • ORJSONResponse; return Pydantic models directly; avoid double validation.
  • Connection pooling (DB, HTTP, Redis); create clients in lifespan.
  • Caching (Redis, fastapi-cache, HTTP cache headers, ETags); GZip middleware for large responses.
  • Pagination, selecting only needed columns, avoiding N+1 queries.
  • uvloop + httptools (included in uvicorn[standard]).
  • Profile with py-spy, pyinstrument; load test with Locust/k6.

What is the GIL and how does it affect FastAPI apps?

The Global Interpreter Lock lets only one thread execute Python bytecode at a time per process. I/O-bound work is fine (the GIL is released during I/O), but CPU-bound Python code in threads does not run in parallel. Solutions: multiple processes, native libraries that release the GIL (NumPy, PyTorch), process pools, or free-threaded Python 3.13+ builds.

How would you implement rate limiting?

Use slowapi (limits-based, decorator per route) or a custom middleware/dependency using Redis (fixed window with INCR+EXPIRE, sliding window with sorted sets, or token bucket). Key on API key / user ID / IP; return 429 with Retry-After. In production often done at the API gateway (NGINX, Kong, Azure APIM).

Implement JWT authentication with OAuth2 password flow.

pwd = PasswordHash.recommended()          # pwdlib (argon2); or passlib bcrypt

What is the Same-Origin Policy (SOP)?

A browser security rule: scripts on a page from one origin can't read responses from another origin. It stops a malicious site from using your logged-in session (cookies) to read your bank or email data. The SOP allows embedding cross-origin resources (<img>, <script>, <link>) and submitting forms, but it blocks JavaScript (fetch/XHR) from reading the responses. CORS is how a server deliberately relaxes the SOP for chosen origins.

What is CORS and why do you need it?

Cross-Origin Resource Sharing is an HTTP-header-based protocol. A server uses it to tell the browser which other origins may read its responses. It's needed whenever the frontend and API are on different origins, e.g., a React app on https://app.example.com or http://localhost:5173 calling a FastAPI backend on https://api.example.com or http://localhost:8000. The browser sends an Origin header. If the response lacks a matching Access-Control-Allow-Origin header, the browser hides the response from JavaScript and reports a CORS error.

Is CORS enforced by the server or the browser? Does CORS protect your API?

The browser enforces it. The server only sends headers. So:

  • curl, Postman, Python requests and server-to-server calls ignore CORS completely. CORS is not authentication or access control, so always protect endpoints with auth.
  • For simple requests, the server still runs the request. The browser only hides the response from JavaScript, so side effects still happen.
  • CORS protects users (their cookies and data in the browser), not your server.

What are "simple" requests and "preflight" requests?

A simple request is sent directly with an Origin header. It must meet all of these conditions:

  • The method is GET, HEAD or POST.
  • Only CORS-safelisted headers are used (Accept, Accept-Language, Content-Language, Content-Type).
  • The Content-Type is text/plain, multipart/form-data or application/x-www-form-urlencoded.

Anything else triggers a preflight: before the real request, the browser sends an OPTIONS request with Origin, Access-Control-Request-Method and Access-Control-Request-Headers. The real request is sent only if the server's reply allows it. In practice most API calls are preflighted, because Content-Type: application/json, an Authorization header, PUT/PATCH/DELETE, or any custom X-* header triggers one.

How do you configure CORS in FastAPI? Explain each CORSMiddleware parameter.

from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com", "http://localhost:5173"],
    allow_origin_regex=r"https://.*\.example\.com",   # optional
    allow_credentials=True,
    allow_methods=["GET", "POST", "PUT", "DELETE"],
    allow_headers=["Authorization", "Content-Type"],
    expose_headers=["X-Total-Count"],
    max_age=600,
)
  • allow_origins: exact origins, with no trailing slash or path. Default [].
  • allow_origin_regex: regex that is full-matched against the origin, useful for subdomains or preview deployments. Escape dots, otherwise . matches any character.
  • allow_methods: default ["GET"].
  • allow_headers: default []. Safelisted headers are always allowed.
  • allow_credentials: default False.
  • expose_headers: default [].
  • max_age: preflight cache time in seconds. Default 600.

The middleware answers preflight OPTIONS requests itself; you don't need @app.options routes. It applies to the whole app, not per router. For different policies, mount a sub-application with its own middleware.

Why can't you use allow_origins=["*"] with allow_credentials=True?

By the CORS spec, browsers reject Access-Control-Allow-Origin: * on credentialed requests (cookies, HTTP auth, client certs). The FastAPI docs say that when credentials are allowed, origins, methods and headers must all be listed explicitly. Some Starlette versions handle this combination by reflecting whatever Origin the request sent. That effectively lets every website make authenticated requests as your users, which is a serious vulnerability. The same risk comes from code that blindly echoes the Origin header, or from a loose regex such as .*example.com, which also matches evilexample.com.

What does the frontend need to do to send cookies cross-origin?

  • Client: fetch(url, { credentials: "include" }) or axios withCredentials: true.
  • Server: allow_credentials=True and an explicit origin.
  • Cookie: SameSite=None; Secure (HTTPS required) for cross-site requests. With Lax/Strict, browsers won't send the cookie on cross-site fetches.
  • Bearer tokens in the Authorization header don't need credentials: "include", but the Authorization header must be in allow_headers.

What is the difference between CORS and CSRF? Does CORS prevent CSRF?

CSRF (Cross-Site Request Forgery) tricks a logged-in user's browser into sending a state-changing request, such as an auto-submitted form POST, that carries their cookies. CORS only controls whether a cross-origin script can read the response. Simple requests such as form POSTs aren't preflighted, so CORS does not prevent CSRF. Defenses against CSRF:

  • SameSite cookies
  • CSRF tokens (double-submit cookie)
  • Requiring a custom header or JSON content type, which forces a preflight
  • Checking Origin/Referer on unsafe methods
  • Using bearer tokens instead of cookies

The browser shows a CORS error but the endpoint works in Postman. How do you debug it?

  1. Open DevTools → Network. Check whether the preflight (OPTIONS) or the actual request failed, and inspect the request Origin and the response headers.
  2. Make sure the origin exactly matches allow_origins: scheme, port, no trailing slash, localhost vs 127.0.0.1.
  3. Make sure the requested method and headers (e.g., Authorization, Content-Type, custom X-*) are allowed. Starlette returns 400 "Disallowed CORS ..." to the preflight otherwise.
  4. Check whether the real error is a 500 or 404. If an unhandled exception occurs, Starlette's ServerErrorMiddleware (outermost) returns a 500 without CORS headers, so the browser reports a misleading CORS error. Check the server logs.
  5. Check for redirects (e.g., a trailing-slash 307 redirect to http:// behind a proxy). Preflights can't follow redirects.
  6. Check whether a reverse proxy, API gateway or CDN strips or duplicates CORS headers. Two Access-Control-Allow-Origin values are also invalid.
  7. For credentials: check that the origin isn't *, that allow_credentials=True is set, and that the cookie has SameSite=None; Secure.

Does the order of middleware matter for CORS?

Yes. In Starlette, the middleware added last runs first (outermost). CORSMiddleware should wrap everything that can reject a request, such as auth, rate-limiting or custom middleware returning 401/429. Otherwise those responses lack CORS headers, and the frontend can't read the error status. It also has to answer the preflight before auth middleware rejects it: preflights never carry credentials, so auth checks shouldn't apply to OPTIONS. Add CORSMiddleware last, or handle auth in dependencies, which run after the middleware.

Do CORS rules apply to WebSockets?

No. Browsers send an Origin header during the WebSocket handshake but don't enforce CORS, and CORSMiddleware doesn't affect WebSocket routes. Validate websocket.headers.get("origin") against an allow-list yourself, and close with code 1008 if it isn't allowed. This prevents Cross-Site WebSocket Hijacking, especially with cookie auth.

How can you avoid CORS entirely?

Serve the frontend and API from the same origin:

  • A reverse proxy (NGINX, Traefik, Azure Front Door) routes / to the SPA and /api to FastAPI.
  • Or FastAPI serves the built SPA via StaticFiles.
  • In development, use the frontend dev-server proxy (Vite server.proxy, CRA proxy).

This removes preflight latency and simplifies cookie auth.

What security best practices apply to FastAPI services?

  • HTTPS everywhere (TLS at proxy), HSTS; TrustedHostMiddleware, HTTPSRedirectMiddleware.
  • Validate all input with Pydantic (lengths, patterns, extra="forbid"); use ORM parameterized queries (prevent SQL injection).
  • Use response_model to avoid leaking sensitive fields.
  • Secrets from env / Key Vault; never commit them. Rotate keys.
  • Rate limiting, request size limits, timeouts.
  • Disable docs in production if not needed (docs_url=None).
  • Don't leak stack traces; generic 500 handler with logging.
  • Secure cookies (HttpOnly, Secure, SameSite); CSRF protection for cookie-based auth.
  • Dependency scanning (pip-audit), least-privilege DB users.

How do you integrate with an external identity provider (Azure AD / Entra ID, Auth0, Keycloak)?

Use OAuth2 Authorization Code (+PKCE) flow for users; the API acts as a resource server validating bearer JWTs: fetch the provider's JWKS (cache it), verify signature (RS256), iss, aud, exp, nbf, and scopes/roles claims. Libraries: fastapi-azure-auth, authlib, PyJWT with PyJWKClient.

Session-based vs token-based authentication?

Session: after login, the server stores session state (in a DB or Redis) and sends a session-ID cookie. Revocation is easy, but the server is stateful, sticky sessions or a shared store are needed, and you need CSRF protection. Token (JWT): the server issues a signed, self-contained token that the client sends in Authorization: Bearer. It is stateless and scales across services, but is hard to revoke before it expires and makes payloads larger. Many apps use short-lived JWT access tokens plus refresh tokens stored in HttpOnly cookies.

What is the structure of a JWT? Is its payload encrypted?

A JWT is three Base64URL-encoded parts joined by dots: header.payload.signature.

  • Header: algorithm and type, e.g., {"alg": "HS256", "typ": "JWT"}.
  • Payload: claims such as sub, exp, iat, iss, aud, roles and scopes.
  • Signature: HMAC (HS256, shared secret) or RSA/ECDSA (RS256/ES256, private key signs and public key verifies).

The payload is only encoded, not encrypted; anyone can read it, so never put secrets in it (use JWE if you need encryption). The signature guarantees integrity. Always verify the signature, pin the allowed algorithms (reject alg: none), and check exp, aud and iss.

How do you implement refresh tokens, logout and token revocation with JWTs?

  • Issue a short-lived access token (5–15 minutes) and a long-lived refresh token (days). Store the refresh token in an HttpOnly, Secure cookie or in the DB.
  • POST /refresh validates the refresh token and issues new tokens. With rotation, each refresh token is single-use; if a used one is presented again, revoke the whole token family because it was likely stolen.
  • Logout/revocation: delete the refresh token server-side; keep a deny-list of access-token jti values in Redis until they expire; or include a token_version claim that you compare with the user record.

Name the OAuth2 flows (grant types) and when each is used.

  • Authorization Code + PKCE: web, SPA and mobile apps where users log in with an identity provider. This is the recommended default.
  • Client Credentials: machine-to-machine calls with no user.
  • Device Code: TVs and CLIs with limited input.
  • Refresh Token: obtain new access tokens.
  • Password (ROPC): the app collects the username and password directly. It is legacy, discouraged except for first-party or simple setups, and is what FastAPI's tutorial uses for simplicity.
  • Implicit: deprecated.

OpenID Connect adds an identity layer on top of OAuth2: an ID token plus a userinfo endpoint.

Why hash passwords with bcrypt/argon2 instead of SHA-256?

General-purpose hashes like SHA-256 are designed to be fast, which lets attackers try billions of guesses per second on GPUs. Password hashing algorithms (argon2id, bcrypt, scrypt) are deliberately slow, include a per-password salt that defeats rainbow tables, and argon2 is also memory-hard. Never encrypt passwords reversibly. Compare hashes with a constant-time check (the library does this), and re-hash on login when you change parameters.

8. Middleware, Lifespan Events & Background Tasks

What is middleware and how do you write one?

Middleware wraps every request/response, running code before the endpoint and after the response is generated.

@app.middleware("http")
async def add_timing(request: Request, call_next):
    start = time.perf_counter()
    response = await call_next(request)
    response.headers["X-Process-Time"] = f"{time.perf_counter() - start:.4f}"
    return response

Class-based: subclass BaseHTTPMiddleware or write a pure ASGI middleware (faster, works with streaming). Middleware added last runs first (outermost). Built-ins: CORSMiddleware, GZipMiddleware, TrustedHostMiddleware, HTTPSRedirectMiddleware, SessionMiddleware.

Middleware vs dependencies — when to use which?

Middleware: cross-cutting concerns for all requests at the HTTP level (logging, timing, CORS, compression, request IDs, security headers); no access to parsed params, not in OpenAPI. Dependencies: per-route/router logic needing typed inputs (auth, DB session, pagination), documented, testable via overrides, can return values to endpoints.

What are lifespan events and how do you use them?

Code executed once at startup and shutdown — e.g., load an ML model, create DB/HTTP connection pools, warm caches, close resources.

from contextlib import asynccontextmanager
@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.model = load_model()
    app.state.http = httpx.AsyncClient()
    yield
    await app.state.http.aclose()

app = FastAPI(lifespan=lifespan)

@app.on_event("startup"/"shutdown") is deprecated in favor of lifespan. Note: lifespan runs per worker process.

What are BackgroundTasks? When should you NOT use them?

def send_email(to: str, body: str): ...
@app.post("/signup")
async def signup(user: UserCreate, bg: BackgroundTasks):
    bg.add_task(send_email, user.email, "Welcome!")
    return {"ok": True}

They run in the same process after the response is sent — good for small fire-and-forget tasks (emails, logging, cache invalidation). Not suitable for heavy/long jobs, jobs needing retries, persistence, scheduling or distribution across machines — tasks are lost if the process dies. Use Celery/RQ/Arq/Azure Queue + worker instead.

How would you add a correlation/request ID to all logs?

Middleware reads X-Request-ID or generates a UUID, stores it in a contextvars.ContextVar (async-safe), adds it to the response header, and a logging filter injects it into each log record. Libraries: asgi-correlation-id. Combine with structured JSON logging and OpenTelemetry tracing.

How do you write a pure ASGI middleware, and why prefer it over BaseHTTPMiddleware?

class SecurityHeadersMiddleware:
    def __init__(self, app): self.app = app
    async def __call__(self, scope, receive, send):
        if scope["type"] != "http":
            return await self.app(scope, receive, send)
        async def send_wrapper(message):
            if message["type"] == "http.response.start":
                message.setdefault("headers", []).append((b"x-content-type-options", b"nosniff"))
            await send(message)
        await self.app(scope, receive, send_wrapper)

app.add_middleware(SecurityHeadersMiddleware)

BaseHTTPMiddleware is easy to write but has overhead, can interfere with streaming responses and background tasks, and has had issues propagating contextvars. A pure ASGI middleware works directly on the scope/receive/send messages: it is faster, supports streaming and WebSockets, and is the right choice for libraries.

How do you integrate Celery (or another task queue) with FastAPI?

# tasks.py
celery = Celery("app", broker="redis://redis:6379/0", backend="redis://redis:6379/1")
@celery.task(bind=True, max_retries=3)
def generate_report(self, user_id): ...

# api
@app.post("/reports", status_code=202)
def create_report(user: CurrentUser):
    task = generate_report.delay(user.id)
    return {"task_id": task.id}

@app.get("/reports/{task_id}")
def status(task_id: str):
    r = AsyncResult(task_id, app=celery)
    return {"state": r.state, "result": r.result if r.ready() else None}

Workers run as separate processes or containers and scale independently. Pass IDs rather than large objects, make tasks idempotent, and configure retries and time limits. Async-native alternatives include Arq, Dramatiq, Taskiq and Azure Service Bus with Functions.

How can you log or modify the raw request body for every route?

Middleware that reads the body consumes the stream. Instead, use a custom APIRoute subclass that overrides get_route_handler(): it reads await request.body() (which caches it), logs or decompresses it, and calls the original handler. Then set APIRouter(route_class=LoggingRoute). The same technique lets you catch exceptions per route with access to the body.

9. Databases, ORMs & Migrations

How do you integrate SQLAlchemy with FastAPI?

engine = create_async_engine("postgresql+asyncpg://...", pool_size=10, pool_pre_ping=True)

One session per request via a yield dependency; engine/pool created once per process.

What is SQLModel?

A library by FastAPI's author combining SQLAlchemy and Pydantic: one class can be both a table model (table=True) and a Pydantic model, reducing duplication. Still recommended to have separate Create/Read/Update models for API contracts.

Sync vs async database access in FastAPI?

Sync drivers (psycopg2, sync SQLAlchemy) should be used in def endpoints (threadpool). Async drivers (asyncpg, aiomysql, aiosqlite, motor for MongoDB) with async def. Async shines with many concurrent I/O-bound requests; beware lazy loading in async SQLAlchemy (use selectinload/joinedload, since implicit IO raises errors).

How do you manage schema migrations?

Use Alembic: alembic init, point env.py to your Base.metadata, alembic revision --autogenerate -m "msg", review, alembic upgrade head. Run migrations as a separate deployment step/job, not at app startup with multiple workers (race conditions).

What is the N+1 query problem and how do you avoid it?

Fetching N parent rows and then issuing one query per row for related data (N+1 queries). Avoid with eager loading (selectinload, joinedload), joins, or batching (DataLoader pattern in GraphQL).

How do you implement pagination?

Offset/limit: simple, supports jumping to pages, but slow for large offsets and inconsistent under inserts. Cursor/keyset: WHERE id > :last_id ORDER BY id LIMIT n; stable and fast for large datasets. Return metadata (total, next_cursor). Library: fastapi-pagination.

How do you handle transactions and concurrency conflicts?

Use async with session.begin(): for atomic units; roll back on exceptions. Handle concurrent updates with optimistic locking (version column; 409 on mismatch) or pessimistic locking (SELECT ... FOR UPDATE). Make POST endpoints idempotent with idempotency keys where needed.

How do you use Redis or MongoDB with FastAPI?

Create the client in lifespan (redis.asyncio.Redis, motor.AsyncIOMotorClient / pymongo async), store on app.state, and expose via dependency. Redis: caching, rate limiting, sessions, pub/sub, queues. MongoDB: use Pydantic models for validation; Beanie ODM integrates natively.

How do you prevent SQL injection in FastAPI apps?

Never build SQL with string formatting from user input (f"SELECT * FROM users WHERE name = '{name}'"). Use ORM queries (select(User).where(User.name == name)) or bound parameters (text("... WHERE name = :name").bindparams(name=name)), which send data separately from the SQL. Validate inputs with Pydantic. For dynamic sort columns, map them to an allow-list, because identifiers can't be bound as parameters. Connect with a least-privilege DB user.

What caching strategies would you use in a FastAPI service?

  • Cache-aside: check Redis first; on a miss, query the DB, store the result with a TTL, and invalidate it on writes.
  • HTTP caching: Cache-Control, ETag/If-None-Match → 304 responses, CDN caching for public GET responses.
  • In-process: functools.lru_cache or cachetools.TTLCache for config and small lookups. Note that each worker has its own copy.

Watch for stale data, cache stampedes (use locks or request coalescing), and leaking private data through shared caches. fastapi-cache2 provides decorators.

11. WebSockets, Streaming, Files & Forms

How do you implement a WebSocket endpoint?

class Manager:
    def __init__(self): self.active: list[WebSocket] = []
    async def connect(self, ws): await ws.accept(); self.active.append(ws)
    def disconnect(self, ws): self.active.remove(ws)
    async def broadcast(self, msg):
        for ws in self.active: await ws.send_text(msg)
manager = Manager()

@app.websocket("/ws/{room}")
async def ws_endpoint(ws: WebSocket, room: str):
    await manager.connect(ws)
    try:
        while True:
            data = await ws.receive_text()
            await manager.broadcast(f"{room}: {data}")
    except WebSocketDisconnect:
        manager.disconnect(ws)

In-memory managers only work in one process; for multiple workers/instances, use Redis pub/sub or a message broker. Authenticate via query token or cookie (browsers cannot set custom headers on WebSockets).

WebSockets vs Server-Sent Events vs long polling?

WebSockets: full-duplex, bidirectional (chat, games, collaborative editing). SSE: one-way server→client over HTTP, automatic reconnect, simpler, proxies-friendly (LLM token streaming, notifications). Long polling: fallback, higher overhead. SSE in FastAPI: StreamingResponse(gen(), media_type="text/event-stream") or sse-starlette.

async def token_stream(prompt):

How do you handle file uploads? bytes vs UploadFile?

@app.post("/upload")

Describe a production deployment architecture.

Client → CDN/WAF → load balancer / reverse proxy (NGINX, Traefik, Azure Front Door / App Gateway) handling TLS → multiple containers each running Uvicorn (Kubernetes, ECS, Azure Container Apps, App Service) → DB with connection pooling (PgBouncer), Redis cache, message queue + workers. How many workers should you run?

A common starting point is (2 × CPU cores) + 1 for I/O-bound apps; for CPU/ML-heavy apps, roughly one worker per core (or per GPU). In Kubernetes, prefer 1 worker per pod and scale pods. Each worker has its own memory (models loaded per worker!), so memory often limits worker count.

What is root_path and why does it matter behind a proxy?

When a proxy serves the app under a prefix (e.g., /api) and strips it, the app must know the prefix to generate correct URLs for docs/OpenAPI. Set FastAPI(root_path="/api") or uvicorn --root-path /api. Also use --proxy-headers / --forwarded-allow-ips so X-Forwarded-* headers determine client IP and scheme.

How do you implement graceful shutdown and health checks?

Uvicorn handles SIGTERM: stops accepting connections, finishes in-flight requests (--timeout-graceful-shutdown), then runs lifespan shutdown. Liveness endpoint returns quickly without dependencies; readiness checks DB/model loaded so the orchestrator only routes traffic when ready.

How do you add logging and observability?

Structured JSON logs (structlog / python-json-logger) with request IDs; configure Uvicorn loggers; avoid logging secrets/PII. Metrics: request rate, latency histograms, error rates (RED). Tracing with OpenTelemetry (opentelemetry-instrumentation-fastapi) exported to Jaeger / Azure Monitor / Datadog. Error tracking with Sentry.

How do you make calls to downstream services resilient?

  • Timeouts on every outbound call: httpx.AsyncClient(timeout=httpx.Timeout(5.0, connect=2.0)). Never rely on the default of waiting forever.
  • Retries with exponential backoff and jitter, only for idempotent operations and transient errors (5xx, timeouts); use tenacity or httpx transports.
  • Circuit breaker: after repeated failures, fail fast for a cool-down period so you don't overload a struggling dependency (pybreaker, aiobreaker).
  • Bulkheads: limit concurrency per dependency with asyncio.Semaphore.
  • Fallbacks: cached or default responses, and graceful degradation (503 + Retry-After).

How do FastAPI microservices communicate with each other?

Synchronous: REST over HTTP (a shared httpx.AsyncClient) or gRPC, which is simple but couples availability. Asynchronous: messaging (Kafka, RabbitMQ, Azure Service Bus, Redis Streams) with events and the outbox pattern for reliable publishing, which decouples services and absorbs spikes. Also needed: service discovery (Kubernetes DNS), an API gateway, distributed tracing (propagate traceparent), shared schemas and contract tests, and eventual consistency with sagas instead of distributed transactions.

How would you scale a FastAPI service to handle 10x traffic?

  1. Measure first: load test and find the bottleneck (CPU, DB, external calls, event loop blocking).
  2. Scale horizontally: keep the service stateless, add replicas behind a load balancer, and autoscale.
  3. Database: connection pooling (PgBouncer), indexes, read replicas, query optimization, caching.
  4. Move slow work to queues and workers; return 202.
  5. Use async I/O, tune workers and the threadpool, use faster serialization.
  6. Put a CDN and edge caching in front of public content; add rate limiting to protect the backend.
  7. Observability and SLOs, so you can see the effect of each change.

14. Serving ML Models with FastAPI

How do you serve a PyTorch model with FastAPI?

@asynccontextmanager
async def lifespan(app):
    model = MyNet()
    model.load_state_dict(torch.load("model.pt", map_location="cpu", weights_only=True))
    model.eval()
    app.state.model = model
    yield

app = FastAPI(lifespan=lifespan)

class PredictIn(BaseModel):
    features: list[float] = Field(min_length=10, max_length=10)
class PredictOut(BaseModel):
    label: int
    prob: float

@app.post("/predict", response_model=PredictOut)
def predict(inp: PredictIn, request: Request):          # sync def -> threadpool
    x = torch.tensor(inp.features).unsqueeze(0)
    with torch.inference_mode():
        probs = request.app.state.model(x).softmax(-1)[0]
    p, idx = probs.max(0)
    return PredictOut(label=idx.item(), prob=p.item())

Key points: load once at startup (not per request), eval() + inference_mode(), validate inputs with Pydantic, use a sync endpoint (or offload) because inference is blocking/CPU/GPU-bound, and set threads (torch.set_num_threads) to avoid oversubscription with multiple workers.

How do you handle high-throughput inference? What is dynamic batching?

Dynamic batching collects concurrent requests for a few milliseconds into one batch, runs a single forward pass (much better GPU utilization), then returns individual results via futures. Implement with an asyncio.Queue + background consumer task, or use dedicated servers (NVIDIA Triton, TorchServe, Ray Serve, BentoML, vLLM/TGI for LLMs) behind FastAPI. Other techniques: ONNX Runtime/TensorRT, quantization, half precision, model warm-up, GPU-per-worker allocation, caching repeated predictions.

How do you handle long-running inference (e.g., video processing)?

Async job pattern: POST returns 202 Accepted + job_id; job pushed to a queue (Celery/Redis, Azure Service Bus); GPU workers process and store results (blob/DB); client polls GET /jobs/{id}, or receives a webhook / WebSocket / SSE notification.

Why does loading a model in each worker matter, and how can you reduce memory?

Each Uvicorn/Gunicorn worker is a separate process with its own copy of the model, so 4 workers = 4× memory (and GPU memory). Mitigations: fewer workers + threadpool/batching; Gunicorn --preload with copy-on-write (CPU only, fragile with PyTorch); move inference into a separate model server shared by API workers; quantize/compress models.

How would you version models and do A/B or canary releases?

Store models in a registry (MLflow, Azure ML) with versions; include model version in responses and logs; route traffic by header or percentage (gateway or in-app router) between model versions; shadow-deploy new models (log predictions without serving them); monitor latency, error rate, data drift and prediction drift before full rollout.

How do PyTorch tensors differ from NumPy arrays?

Their APIs are similar, but tensors also:

  • Run on GPUs and other accelerators
  • Track gradients for autograd
  • Support more dtypes (bf16, fp8)
  • Integrate with nn, torch.compile and distributed training

Conversion: torch.from_numpy(a) and t.numpy() share memory on the CPU. A GPU tensor or one that requires grad needs t.detach().cpu().numpy() first. Note that NumPy defaults to float64 while PyTorch defaults to float32.

What is the difference between *, @, torch.mm, torch.matmul and torch.bmm?

* (torch.mul) is element-wise multiplication with broadcasting. @ / torch.matmul is matrix multiplication: dot product for 1-D, matrix product for 2-D, and batched with broadcasting for N-D. torch.mm handles strictly 2-D matrices with no broadcasting. torch.bmm handles strictly 3-D batches (B, n, m) @ (B, m, p). Use x.T for 2-D transpose and x.mT for transposing the last two dims of a batch.

How do you get Python values out of a tensor?

t.item() for a single-element tensor, t.tolist() for nested lists, t.numpy() for NumPy. Each call on a GPU tensor copies data to the host and synchronizes, so avoid them in hot loops.

Explain tensor storage, strides and views.

A tensor is a view over a 1-D contiguous storage buffer, defined by:

  • An offset
  • A shape
  • Strides: how many elements to skip in storage to move one step along each dim

A contiguous (3, 4) tensor has strides (4, 1); its transpose has shape (4, 3) and strides (1, 4), using the same storage with no copy. Slicing, view, transpose, expand and indexing with slices create views, and modifying a view modifies the original. Advanced indexing (index tensors, boolean masks) creates copies. Check a.untyped_storage().data_ptr() == b.untyped_storage().data_ptr() to see whether two tensors share memory.

What is PyTorch and what are its main components?

PyTorch is an open-source deep learning framework (Meta / Linux Foundation) offering GPU-accelerated tensors and automatic differentiation with a Pythonic, eager-execution (define-by-run) style. Components: torch (tensors, ops), torch.autograd, torch.nn (layers, losses), torch.optim, torch.utils.data (Dataset/DataLoader), torch.cuda/mps, torch.distributed, torch.compile, torch.export/torch.onnx, torch.ao.quantization, plus domain libraries (torchvision, torchaudio, torchtext legacy).

What is a tensor? How do you create tensors?

A tensor is a multi-dimensional array with a dtype, device, shape, strides and optional gradient tracking.

torch.zeros(2, 3); torch.ones(2, 3); torch.empty(2, 3)  # empty = uninitialized

torch.from_numpy(arr)  # shares memory with NumPy array

torch.tensor vs torch.Tensor vs torch.from_numpy vs torch.as_tensor?

torch.tensor(data) (factory function) always copies and infers dtype. torch.Tensor(...) is the class constructor; defaults to float32 and behaves inconsistently (torch.Tensor(3) creates an uninitialized length-3 tensor) — avoid. torch.from_numpy shares memory with the NumPy array (changes reflect in both; CPU only). torch.as_tensor shares memory when possible, otherwise copies.

Explain view, reshape, permute, transpose, contiguous.

  • view(shape): returns a new view sharing storage; requires compatible (usually contiguous) memory layout, else error.
  • reshape(shape): returns a view if possible, otherwise copies — always works.
  • transpose(d0, d1): swaps two dims; permute(*dims): arbitrary reordering. Both return non-contiguous views (only strides change).
  • contiguous(): returns a tensor with row-major memory layout (copies if needed); required before view after permute.
  • Also: squeeze/unsqueeze (remove/add size-1 dims), flatten, unflatten, expand (broadcast view, no copy) vs repeat (copies).

What is broadcasting?

Rules for operating on tensors of different shapes without copying: align shapes from the trailing dimension; dimensions are compatible if equal or one of them is 1 (or missing); size-1 dims are virtually expanded. E.g., (32, 1, 5) + (4, 5) → (32, 4, 5). Pitfall: (N,) - (N,1) silently produces (N,N), a common bug in loss computations.

What are in-place operations? Why should you be careful with them?

Ops with trailing underscore (x.add_(1), relu_, x[0] = 5) modify data in place, saving memory. Risks: they can overwrite values autograd saved for backward → RuntimeError: one of the variables needed for gradient computation has been modified by an inplace operation; in-place on a leaf tensor that requires grad is disallowed; and they can create subtle aliasing bugs with views.

What dtypes does PyTorch support and when do you use each?

float32 (default training), float16/bfloat16 (mixed precision; bf16 has float32's range, less precision, no loss scaling needed), float64 (scientific precision), int64/long (class indices for CrossEntropyLoss, embedding indices), int8/uint8 (quantization, images), bool (masks), float8 (H100 training/inference), complex64. Convert with x.float(), x.to(torch.bfloat16).

16. Autograd & Computational Graphs

How does autograd work?

Autograd implements reverse-mode automatic differentiation. When operations run on tensors with requires_grad=True, PyTorch records a dynamic computational graph (DAG) where each result has a grad_fn (e.g., MulBackward0) pointing to its inputs. Calling loss.backward() traverses the graph from the output to the leaves, applying the chain rule (vector-Jacobian products), and accumulates gradients into .grad of leaf tensors. The graph is freed after backward by default.

x = torch.tensor(2.0, requires_grad=True)
y = x**3 + 2*x
y.backward()
print(x.grad)   # 3*x^2 + 2 = 14

What is a dynamic (define-by-run) graph and why is it useful?

The graph is built on the fly during each forward pass, so it can differ per iteration. You can use native Python control flow (if/loops/recursion), variable-length inputs, and debug with print/pdb. Static graphs (TF1) are defined then executed, enabling global optimizations; PyTorch recovers these via torch.compile.

What are leaf tensors? Why is .grad None for intermediate tensors?

Leaf tensors are created by the user (not the result of a tracked op), e.g., model parameters. Only leaves with requires_grad=True retain .grad by default to save memory. For a non-leaf, call t.retain_grad() before backward, or use hooks.

Why do gradients accumulate and why call optimizer.zero_grad()?

backward() adds to existing .grad values. This enables gradient accumulation across micro-batches and summing gradients from multiple losses, but means you must reset gradients each step. zero_grad(set_to_none=True) (default in PyTorch 2) sets them to None, saving memory and a kernel.

torch.no_grad() vs torch.inference_mode() vs model.eval() vs detach()?

  • model.eval(): switches module behavior (Dropout off, BatchNorm uses running stats). Does not disable gradient tracking.
  • torch.no_grad(): disables graph recording inside the block — saves memory/compute; tensors can still later be used in autograd.
  • torch.inference_mode(): stricter, faster version of no_grad (also skips version counters/view tracking); resulting tensors can't be used in autograd later. Best for pure inference.
  • tensor.detach(): returns a tensor sharing storage but cut off from the graph (e.g., for target networks, logging, stopping gradient flow).

For evaluation use both model.eval() and no_grad/inference_mode.

What does backward() need for a non-scalar output?

A gradient argument (the vector in the vector-Jacobian product) of the same shape: y.backward(torch.ones_like(y)). Usually you reduce to a scalar loss first.

What is retain_graph=True and create_graph=True?

retain_graph=True keeps the graph's saved tensors so you can call backward again through it (e.g., multiple losses sharing parts; GAN tricks) — otherwise a second backward errors. create_graph=True builds a graph of the backward pass itself, enabling higher-order derivatives (gradient penalty in WGAN-GP, MAML, Hessian-vector products).

How do you compute gradients without populating .grad?

torch.autograd.grad(outputs, inputs, create_graph=False) returns gradients as a tuple, useful for gradient penalties and meta-learning. torch.func (functorch) offers grad, vmap, jacrev, jacfwd, hessian for functional transforms, per-sample gradients, and forward-mode AD.

How do you freeze parameters?

for p in model.backbone.parameters():
    p.requires_grad_(False)
optimizer = torch.optim.AdamW(filter(lambda p: p.requires_grad, model.parameters()), lr=1e-3)

Frozen layers still need eval() if they contain BatchNorm and you want their running stats fixed.

What is gradient checkpointing?

A memory/compute trade-off: instead of storing all intermediate activations, store only some, and recompute the rest during backward. torch.utils.checkpoint.checkpoint(block, x, use_reentrant=False). Reduces activation memory (roughly from O(n) to O(√n) layers) at ~20–30% extra compute. Widely used for large transformers.

17. nn.Module & Building Models

What is nn.Module? Write a simple model.

Base class for all layers and models. It registers parameters, buffers and submodules assigned as attributes; provides parameters(), state_dict(), to(), train()/eval(), hooks, etc.

class MLP(nn.Module):
    def __init__(self, in_dim, hidden, out_dim, p=0.2):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden), nn.ReLU(), nn.Dropout(p),
            nn.Linear(hidden, out_dim))
    def forward(self, x):
        return self.net(x)

model = MLP(784, 256, 10)
logits = model(x)       # call the module, not model.forward(x)

Why call model(x) instead of model.forward(x)?

__call__ runs forward pre-hooks, forward, forward hooks and backward hook registration. Calling forward directly bypasses hooks (used by profilers, quantization, FSDP, etc.).

Why must you call super().__init__(), and why do submodules in a Python list not get registered?

nn.Module.__init__ sets up internal dicts (_parameters, _modules, _buffers); without it, assigning a layer raises an error. Modules stored in a plain list/dict are invisible to parameters(), .to(device) and state_dict → use nn.ModuleList / nn.ModuleDict (and nn.ParameterList).

nn.Sequential vs nn.ModuleList vs nn.ModuleDict?

Sequential: ordered container with its own forward that chains modules. ModuleList: registered list; no forward — you iterate manually (e.g., transformer layers with skip connections). ModuleDict: registered dict keyed by name (multi-head models, task-specific heads).

Parameters vs buffers?

nn.Parameter: learnable tensor (requires grad), returned by parameters(), updated by optimizer. Buffers (self.register_buffer("running_mean", t, persistent=True)): non-learnable state saved in state_dict and moved with .to() — e.g., BatchNorm running stats, positional encodings, masks. persistent=False excludes it from state_dict.

What does model.train() vs model.eval() change?

Sets the training flag recursively. Affects layers like Dropout (active in train, identity in eval) and BatchNorm (batch statistics + update running stats in train; running stats in eval). Forgetting eval() at inference gives noisy, batch-dependent predictions.

What is a state_dict? How do you save and load models?

An OrderedDict mapping parameter/buffer names to tensors. Recommended:

Compare BatchNorm, LayerNorm, GroupNorm, InstanceNorm and RMSNorm.

  • BatchNorm: normalizes each channel across the batch (and spatial dims). Needs reasonably large batches, and behaves differently in train and eval (running stats). Standard in CNNs.
  • LayerNorm: normalizes across the features of each sample. Independent of batch size and identical in train and eval. Standard in transformers and RNNs.
  • GroupNorm: normalizes groups of channels per sample. Good for small batches, e.g., detection and segmentation.
  • InstanceNorm: normalizes per sample per channel. Used for style transfer.
  • RMSNorm: LayerNorm without mean-centering, scaling by root-mean-square only. Cheaper; used in LLaMA and other modern LLMs.

What are weight tying and parametrizations (weight norm, spectral norm)?

Weight tying shares one parameter between layers, e.g., a language model's input embedding and its output projection: self.lm_head.weight = self.embed.weight. Parametrizations (torch.nn.utils.parametrize) compute a weight from underlying parameters on every access: parametrizations.weight_norm, spectral_norm (constrains the Lipschitz constant, used in GAN discriminators) and orthogonal. You can register custom ones, e.g., to force symmetric matrices.

18. Loss Functions, Optimizers & LR Schedulers

What inputs does nn.CrossEntropyLoss expect?

Raw, unnormalized logits of shape (N, C) (or (N, C, d1, ...) for segmentation) and targets as class indices (N,) of dtype long (or class probabilities of shape (N, C)). It internally combines LogSoftmax + NLLLoss for numerical stability — do not apply softmax before it. Options: weight (class imbalance), ignore_index (padding, default -100), label_smoothing, reduction.

BCELoss vs BCEWithLogitsLoss?

BCELoss expects probabilities (after sigmoid); numerically unstable. BCEWithLogitsLoss takes logits and fuses sigmoid + BCE using the log-sum-exp trick — preferred. Supports pos_weight for imbalance. Used for binary and multi-label classification (targets float, same shape as logits).

How do you write a custom loss?

class FocalLoss(nn.Module):
    def __init__(self, gamma=2.0, alpha=0.25):
        super().__init__(); self.gamma, self.alpha = gamma, alpha
    def forward(self, logits, targets):
        bce = F.binary_cross_entropy_with_logits(logits, targets, reduction="none")
        p_t = torch.exp(-bce)
        return (self.alpha * (1 - p_t) ** self.gamma * bce).mean()

Any differentiable tensor ops work; autograd handles gradients.

Compare SGD, Momentum, Adam and AdamW.

  • SGD: w -= lr * g. Simple; with momentum (0.9) and Nesterov often generalizes best for CNNs.
  • Momentum: accumulates velocity to dampen oscillations and speed through ravines.
  • RMSprop / Adagrad: per-parameter adaptive learning rates.
  • Adam: momentum (1st moment) + RMSprop (2nd moment) with bias correction; fast convergence, less tuning.
  • AdamW: Adam with decoupled weight decay (applied directly to weights instead of via gradient), which regularizes correctly; standard for transformers.

Others: LAMB/LARS (large batch), Adafactor (memory-efficient), Lion, Sophia; 8-bit Adam (bitsandbytes).

What learning rate schedulers exist and how are they used?

StepLR, MultiStepLR, ExponentialLR, CosineAnnealingLR, CosineAnnealingWarmRestarts, OneCycleLR, LinearLR (warmup), SequentialLR (chain warmup + cosine), ReduceLROnPlateau (step with a metric), LambdaLR (custom). Call scheduler.step() after optimizer.step() — per epoch or per iteration depending on the scheduler (OneCycle/warmup are per iteration). Warmup stabilizes early training for transformers/large batches.

What is gradient clipping and when do you use it?

torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0) rescales gradients if their global norm exceeds a threshold; clip_grad_value_ clips each element. Prevents exploding gradients in RNNs/transformers. With AMP, call scaler.unscale_(optimizer) before clipping.

How do you implement L1/L2 regularization?

L2: weight_decay in the optimizer (prefer AdamW for adaptive optimizers). L1: add manually: loss = loss + lam * sum(p.abs().sum() for p in model.parameters()). Other regularizers: dropout, data augmentation, label smoothing, early stopping, stochastic depth, mixup/cutmix.

How do you choose a good learning rate?

Start from known defaults: AdamW 1e-3 to 3e-4 for training from scratch, 1e-5 to 5e-5 for fine-tuning transformers; SGD 0.1 with momentum for ResNets at batch 256. Run an LR range test: increase the LR exponentially over a few hundred steps, plot loss against LR, and pick a value somewhat below where the loss falls fastest, before it diverges. Combine it with warmup and a decay schedule (cosine or one-cycle). Tune the LR first; it is the most important hyperparameter.

What are EMA of weights and Stochastic Weight Averaging (SWA)?

Both average model weights to reach flatter minima that generalize better. EMA keeps a shadow copy updated each step (ema = decay·ema + (1-decay)·w, e.g., decay 0.999) and is used for evaluation; it is common in diffusion models, YOLO and semi-supervised learning. SWA averages weights from several points late in training, typically with a constant or cyclic LR.

How do you combine multiple losses (multi-task learning)?

Use a weighted sum, loss = w1*l1 + w2*l2, and call a single backward(). Tune the weights so no task dominates; check each task's gradient magnitude. Adaptive alternatives: uncertainty weighting (learnable log-variances per task), GradNorm, and PCGrad for conflicting gradients. Log each loss separately.

20. Training Loop, Evaluation & Checkpointing

Define epoch, batch, batch size, iteration and step.

A batch is a subset of samples processed together in one forward/backward pass. Batch size is the number of samples in that batch. An iteration or step is one parameter update; with gradient accumulation, one step covers several micro-batches. An epoch is one full pass over the training set. Iterations per epoch = ceil(N / batch_size), i.e., len(loader). Example: 50,000 images with batch size 100 gives 500 iterations per epoch.

What are the five essential steps of training in PyTorch?

  1. Forward pass: pred = model(x).
  2. Compute the loss: loss = criterion(pred, y).
  3. Zero the gradients: optimizer.zero_grad().
  4. Backward pass: loss.backward() computes gradients.
  5. Update the parameters: optimizer.step().

Everything else is built around these steps: device moves, AMP, clipping, scheduling, logging.

Write a standard PyTorch training and validation loop.

def train_one_epoch(model, loader, criterion, optimizer, scheduler, device):
    model.train()
    total, correct, running = 0, 0, 0.0
    for x, y in loader:
        x, y = x.to(device, non_blocking=True), y.to(device, non_blocking=True)
        optimizer.zero_grad(set_to_none=True)   # 1. reset grads
        logits = model(x)                       # 2. forward
        loss = criterion(logits, y)             # 3. loss
        loss.backward()                         # 4. backward
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        optimizer.step()                        # 5. update
        scheduler.step()                        # per-iteration scheduler
        running += loss.item() * x.size(0)
        correct += (logits.argmax(1) == y).sum().item(); total += x.size(0)
    return running / total, correct / total

@torch.no_grad()
def evaluate(model, loader, criterion, device):
    model.eval()
    total, correct, running = 0, 0, 0.0
    for x, y in loader:
        x, y = x.to(device), y.to(device)
        logits = model(x)
        running += criterion(logits, y).item() * x.size(0)
        correct += (logits.argmax(1) == y).sum().item(); total += x.size(0)
    return running / total, correct / total

Why use loss.item() when logging?

.item() converts a 1-element tensor to a Python number, detaching it. Accumulating total_loss += loss keeps the entire graph of every iteration alive → memory leak. Note .item() forces a GPU sync; for max speed accumulate detached tensors and sync occasionally.

How do you implement gradient accumulation?

accum = 4
for i, (x, y) in enumerate(loader):
    loss = criterion(model(x), y) / accum     # scale so gradients average
    loss.backward()
    if (i + 1) % accum == 0:
        optimizer.step(); optimizer.zero_grad()

Simulates a batch size of accum × batch_size when GPU memory is limited. BatchNorm still sees the small micro-batch. In DDP, use model.no_sync() on non-update steps to skip redundant all-reduce.

How do you implement early stopping?

Track the best validation metric; save a checkpoint when it improves; increment a counter otherwise; stop when the counter exceeds patience. Restore the best weights at the end. Libraries like Lightning provide EarlyStopping callbacks.

How do you track experiments and metrics?

TensorBoard (torch.utils.tensorboard.SummaryWriter), Weights & Biases, MLflow, Neptune; metrics via torchmetrics (handles distributed accumulation correctly). Log losses, LR, gradient norms, metrics, sample predictions, hyperparameters, git commit and seeds.

What is the order of optimizer.step(), scheduler.step() and zero_grad()?

zero_grad() → forward → loss → backward() → (clip) → optimizer.step() → scheduler.step(). zero_grad can also come right after step; it just must happen before the next backward. Calling the scheduler before the optimizer skips the first LR value (PyTorch warns).

How do you compute evaluation metrics correctly?

Accumulate predictions or counts over the whole validation set, then compute the metric. Averaging per-batch F1 or AUC is wrong, because those metrics aren't decomposable and the last batch may be smaller. torchmetrics handles this, including syncing across GPUs:

print(f1.compute()); f1.reset()

How do you tune hyperparameters for a PyTorch model?

Tune the learning rate first, then batch size, weight decay, dropout, depth/width and augmentation strength. Use random search or Bayesian optimization (Optuna, Ray Tune) rather than grid search, with early pruning of bad trials (median or Hyperband pruners). Search the LR on a log scale and evaluate on the validation set only. Fix seeds and log everything; scale up only the best configurations.

21. GPU, Mixed Precision & Performance

What is Automatic Mixed Precision (AMP) and how do you use it?

AMP runs suitable ops (matmul, conv) in float16/bfloat16 for speed (Tensor Cores) and memory savings, while keeping precision-sensitive ops (reductions, softmax, losses) in float32. With fp16, a GradScaler multiplies the loss to avoid gradient underflow, then unscales before the update and skips steps with inf/NaN.

scaler = torch.amp.GradScaler("cuda")
for x, y in loader:
    optimizer.zero_grad()
    with torch.autocast(device_type="cuda", dtype=torch.float16):
        loss = criterion(model(x), y)
    scaler.scale(loss).backward()
    scaler.unscale_(optimizer); clip_grad_norm_(model.parameters(), 1.0)
    scaler.step(optimizer); scaler.update()

With bfloat16 (Ampere+), no scaler is needed thanks to its wide exponent range.

How do you diagnose and fix CUDA out-of-memory (OOM) errors?

  • Reduce batch size; use gradient accumulation.
  • Mixed precision (bf16/fp16); gradient checkpointing.
  • Avoid keeping graphs alive (loss.item(), detach() for logged tensors); use no_grad in eval.
  • Delete unused tensors, torch.cuda.empty_cache() (releases cached blocks to other processes; doesn't fix leaks).
  • Use memory-efficient optimizers (8-bit Adam, Adafactor), FSDP/ZeRO sharding, CPU offload, LoRA for fine-tuning.
  • Inspect with torch.cuda.memory_summary(), max_memory_allocated(), memory snapshots (torch.cuda.memory._record_memory_history).
  • Set PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True to reduce fragmentation.

What are common ways to speed up PyTorch training?

  • Fix data loading bottlenecks: num_workers, pin_memory, faster decoding, pre-processed/cached data.
  • AMP (bf16/fp16), TF32 (torch.backends.cuda.matmul.allow_tf32 = True or torch.set_float32_matmul_precision("high")).
  • torch.compile(model); fused optimizers (AdamW(fused=True)); fused attention (F.scaled_dot_product_attention → FlashAttention).
  • cudnn.benchmark = True for fixed input sizes; channels_last memory format for CNNs.
  • Avoid host-device syncs in the loop (.item(), .cpu(), printing, nonzero).
  • Larger batches with LR scaling; multi-GPU DDP.
  • CUDA Graphs for small, static workloads (mode="reduce-overhead").

CUDA ops are asynchronous — when timing manually, call torch.cuda.synchronize() or use CUDA events. Also: nvidia-smi, Nsight Systems, GPU utilization to detect data-loading stalls.

Why are CUDA operations asynchronous and what forces synchronization?

Kernels are queued on a CUDA stream and the Python thread continues, overlapping CPU and GPU work. Synchronization happens on .item(), .cpu(), .numpy(), print(tensor), torch.cuda.synchronize(), data-dependent shapes (nonzero, boolean masking), and non-pinned copies. Errors may be reported at a later line; set CUDA_LAUNCH_BLOCKING=1 to debug.

What is channels_last memory format?

Stores NCHW tensors physically as NHWC. Convolutions on Tensor Cores (especially with AMP) run faster in this layout. Use model.to(memory_format=torch.channels_last) and x.to(memory_format=torch.channels_last).

How do you use multiple GPUs on a single machine? Why prefer DDP over DataParallel?

nn.DataParallel: single process, multi-thread; replicates the model every iteration, scatters inputs, gathers outputs on GPU 0 — GIL contention and imbalanced memory; legacy. DistributedDataParallel: one process per GPU, each with a model replica; gradients are all-reduced in buckets overlapped with backward. Faster, scales to multiple nodes, recommended even for a single node.

What are CUDA streams and events?

A stream is a queue of GPU operations that execute in order. Operations on different streams can overlap, e.g., copying the next batch while computing on the current one. PyTorch uses one default stream per device; torch.cuda.Stream() with with torch.cuda.stream(s): runs work on another stream, and you sync with wait_stream or record_stream. Events mark points in a stream for synchronization and accurate GPU timing:

start, end = torch.cuda.Event(enable_timing=True), torch.cuda.Event(enable_timing=True)
start.record(); y = model(x); end.record(); torch.cuda.synchronize()
print(start.elapsed_time(end), "ms")

How do you estimate the GPU memory needed for training?

With mixed-precision Adam, model state needs roughly 16 bytes per parameter:

  • fp32 master weights: 4 bytes
  • Adam moments (m and v): 8 bytes
  • Gradients and bf16 weights: about 4 bytes

A 7B model therefore needs about 112 GB before counting activations, which scale with batch size × sequence length × hidden size × layers, plus framework overhead. Inference needs roughly 2 bytes per parameter in bf16 (14 GB for 7B), or 0.5 bytes in 4-bit, plus the KV-cache. This explains why FSDP, checkpointing, LoRA and quantization exist.

    if dist.get_rank() == 0: torch.save(model.module.state_dict(), "m.pt")
    dist.destroy_process_group()

# torchrun --nproc_per_node=4 --nnodes=1 train.py

Each process computes forward/backward on its data shard; during backward, gradient buckets are averaged with all-reduce (ring/tree via NCCL), so all replicas apply identical updates. Effective batch = per-GPU batch × world size (scale LR accordingly). Use SyncBatchNorm if per-GPU batches are small.

Define world size, rank, local rank, backend.

World size: total number of processes. Rank: global process ID (0 is usually the "main" for logging/saving). Local rank: process ID within a node (maps to GPU index). Backend: communication library — NCCL (GPU, fastest), Gloo (CPU), MPI. torchrun sets RANK, LOCAL_RANK, WORLD_SIZE, MASTER_ADDR, MASTER_PORT and supports elastic/fault-tolerant training.

What are collective communication operations?

all_reduce (sum/avg across ranks, result on all — gradient sync), broadcast (from one rank to all — initial weights), all_gather (collect tensors from all), reduce_scatter (reduce then shard — used by FSDP/ZeRO), gather, scatter, barrier (synchronize).

What are data, tensor, pipeline and sequence parallelism?

  • Data parallelism: replicate model, split data (DDP).
  • Fully Sharded Data Parallel (FSDP / ZeRO-3): shard parameters, gradients and optimizer states across GPUs; all-gather parameters just in time for each layer's forward/backward. Enables models larger than one GPU's memory.
  • Tensor parallelism: split individual layers (matmuls) across GPUs (Megatron-LM); needs fast interconnect (NVLink).
  • Pipeline parallelism: split layers into stages on different GPUs; micro-batches fill the pipeline to reduce bubbles (GPipe, 1F1B).
  • Sequence/context parallelism: split long sequences across devices.
  • 3D parallelism combines data + tensor + pipeline for very large LLMs.

Explain ZeRO stages and FSDP.

ZeRO (DeepSpeed) removes redundancy in data parallelism. Stage 1: shard optimizer states. Stage 2: + gradients. Stage 3: + parameters. Memory per GPU drops roughly linearly with GPU count at the cost of more communication. PyTorch's native equivalent is FSDP (FullyShardedDataParallel, and FSDP2 via fully_shard), with options for mixed precision, CPU offload, activation checkpointing and auto-wrap policies (wrap each transformer block).

What tools simplify distributed training?

PyTorch Lightning / Fabric, Hugging Face Accelerate & Trainer, DeepSpeed, torchtitan, Megatron-LM, Ray Train, Horovod. They abstract launching, DDP/FSDP wrapping, AMP, checkpointing and logging.

How do you scale the learning rate with batch size?

Linear scaling rule: multiply LR by k when batch size grows by k (SGD), with warmup to avoid early instability. For Adam, square-root scaling is often used. Very large batches may need LARS/LAMB.

What are DTensor and DeviceMesh?

DeviceMesh describes a multi-dimensional layout of devices, e.g., init_device_mesh("cuda", (2, 4), mesh_dim_names=("dp", "tp")) for 2-way data parallelism × 4-way tensor parallelism. DTensor is a tensor sharded or replicated across a mesh according to placements (Shard(dim), Replicate(), Partial()), and PyTorch inserts the required collectives automatically. They underpin FSDP2 (fully_shard), the tensor-parallel API (parallelize_module with ColwiseParallel/RowwiseParallel) and 2D/3D parallelism in torchtitan.

How do you initialize a model too large for CPU or GPU memory?

Create it on the meta device, where tensors have shapes but no storage: with torch.device("meta"): model = Big(). Then shard it (FSDP) and materialize only the local shards with model.to_empty(device="cuda"), followed by initialization or checkpoint loading. Hugging Face's device_map="auto" / low_cpu_mem_usage use the same idea.

Distributed training hangs or crashes. How do you debug it?

  • Hangs are usually caused by ranks executing different collectives: data-dependent branches, uneven numbers of batches (use drop_last or the Join context), or only rank 0 calling a collective, e.g., during evaluation.
  • Set NCCL_DEBUG=INFO, TORCH_DISTRIBUTED_DEBUG=DETAIL and TORCH_NCCL_ASYNC_ERROR_HANDLING=1, and use a timeout in init_process_group. The flight recorder (TORCH_NCCL_TRACE_BUFFER_SIZE) dumps the last collectives on timeout.
  • "Expected to have finished reduction" means some parameters received no gradient. Fix the model, or pass find_unused_parameters=True (slower).
  • Check network interfaces (NCCL_SOCKET_IFNAME), firewall rules and MASTER_ADDR/PORT.

23. Advanced: Custom Autograd, Hooks, torch.compile & TorchScript

How do you write a custom autograd Function?

class ClampGrad(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, lo, hi):
        ctx.save_for_backward(x); ctx.lo, ctx.hi = lo, hi
        return x.clamp(lo, hi)
    @staticmethod
    def backward(ctx, grad_out):
        (x,) = ctx.saved_tensors
        mask = (x >= ctx.lo) & (x <= ctx.hi)
        return grad_out * mask, None, None    # one grad per forward input

y = ClampGrad.apply(x, -1.0, 1.0)

Used for non-differentiable ops (straight-through estimators), memory-efficient custom gradients, or wrapping custom CUDA/Triton kernels. Verify with torch.autograd.gradcheck (double precision).

What are hooks in PyTorch? Give use cases.

  • Tensor hooks: t.register_hook(lambda g: g * 0.5) — inspect/modify gradients.
  • Forward hooks: module.register_forward_hook(fn(module, inp, out)) — extract intermediate features/activations, feature maps for Grad-CAM, debugging NaNs.
  • Forward pre-hooks: modify inputs before forward.
  • Full backward hooks: register_full_backward_hook — inspect gradients w.r.t. module inputs/outputs.
  • State-dict hooks for compatibility when loading old checkpoints.

They return a handle; call handle.remove() to avoid leaks.

feats = {}
h = model.layer4.register_forward_hook(lambda m, i, o: feats.__setitem__("l4", o.detach()))

What is torch.compile and how does it work?

Introduced in PyTorch 2.0: model = torch.compile(model) JIT-compiles the model for speed (often 1.3–2x). Pipeline:

  • TorchDynamo captures Python bytecode into FX graphs safely, inserting graph breaks for unsupported Python code and falling back to eager.
  • AOTAutograd traces the backward graph ahead of time.
  • PrimTorch decomposes ~2000 ops into a smaller primitive set.
  • TorchInductor generates fused kernels (Triton on GPU, C++/OpenMP on CPU).

Modes: "default", "reduce-overhead" (CUDA graphs), "max-autotune". Use dynamic=True for varying shapes; fullgraph=True to error on graph breaks. First call is slow (compilation); recompiles on shape/dtype/guard changes. Debug with TORCH_LOGS="graph_breaks,recompiles".

What is TorchScript? Tracing vs scripting?

TorchScript is an intermediate representation that serializes models for execution without Python (C++ libtorch, mobile). Tracing (torch.jit.trace(model, example)) records ops executed for one example input — data-dependent control flow is frozen (silent bugs). Scripting (torch.jit.script) compiles Python source, preserving control flow, but supports a subset of Python. TorchScript is now in maintenance mode; torch.export is the recommended path forward.

What is torch.export?

Produces a sound, whole-graph ExportedProgram (ATen-level FX graph) ahead of time, with no graph breaks allowed and explicit dynamic shape specifications (Dim). It is the foundation for AOTInductor (compiled .so for server deployment), ExecuTorch (mobile/edge) and the new ONNX exporter (torch.onnx.export(..., dynamo=True)).

What is FX?

torch.fx is a toolkit for capturing and transforming programs as Python-level graphs (symbolic_trace → GraphModule). Used for operator fusion, quantization (FX graph mode), feature extraction (torchvision.models.feature_extraction), and custom compiler passes.

How do you write custom CUDA/C++ extensions or Triton kernels?

C++/CUDA: torch.utils.cpp_extension (load_inline or setuptools CUDAExtension), registering ops with TORCH_LIBRARY so they work with torch.compile. Triton: write Python-like GPU kernels with @triton.jit; wrap them with torch.library.triton_op / custom_op. Used for fused attention, custom activations, quantized matmuls.

What is torch.func (functorch) and vmap?

JAX-like composable function transforms. vmap auto-vectorizes a function over a batch dimension (no manual batching); grad/jacrev/hessian compute derivatives functionally; functional_call(model, params, x) runs a module with given parameters. Use cases: per-sample gradients (differential privacy), ensembling, meta-learning, Jacobians for physics-informed nets.

How does PyTorch execute an operation internally (dispatcher, ATen)?

A Python call such as torch.add(a, b) goes through C++ bindings into the dispatcher. The dispatcher picks a kernel based on the inputs' dispatch keys, processed in priority order:

  • Autograd: records grad_fn
  • Autocast: casts dtypes
  • Functionalization and Python modes
  • The backend: CPU, CUDA, MPS, Meta, sparse, quantized, etc.

The actual kernels live in ATen, the C++ tensor library. This layering is how one API supports many devices, how subclasses such as DTensor work, and how torch.library custom ops plug in.

What are saved-tensor hooks and activation offloading?

torch.autograd.graph.saved_tensors_hooks(pack, unpack) intercepts tensors that autograd saves for backward. You can compress them, quantize them, or move them to CPU (torch.autograd.graph.save_on_cpu(pin_memory=True)) and bring them back during backward. This trades PCIe bandwidth for GPU memory and complements activation checkpointing.

What is FlexAttention?

torch.nn.attention.flex_attention lets you express attention variants (causal, sliding window, ALiBi, document masking, soft-capping) as small Python score_mod/mask_mod functions. torch.compile then generates fused FlashAttention-style kernels, and block masks skip fully masked blocks. You get custom attention without writing CUDA.

What is quantization? Explain dynamic, static and quantization-aware training.

Representing weights/activations in lower precision (int8, int4, fp8) to shrink models (~4x for int8) and speed up inference with small accuracy loss.

  • Dynamic (post-training): weights quantized ahead of time, activations quantized on the fly. Easy; great for LSTMs/Linear-heavy models on CPU. torch.ao.quantization.quantize_dynamic(model, {nn.Linear}, dtype=torch.qint8).
  • Static (post-training): weights and activations quantized; requires calibration data to compute activation ranges (observers); fuse Conv-BN-ReLU first. Best CPU speedups for CNNs.
  • Quantization-aware training (QAT): inserts fake-quant ops during training/fine-tuning so the model learns to tolerate quantization noise; best accuracy.

Modern stack: torchao (int8/int4 weight-only, fp8, PT2E quantization), bitsandbytes/GPTQ/AWQ for LLMs.

What is pruning?

Removing weights (unstructured: individual weights by magnitude — sparse but needs special hardware to speed up) or whole channels/heads/layers (structured: real speedups). torch.nn.utils.prune.l1_unstructured(module, "weight", amount=0.3), then prune.remove to make it permanent. Usually followed by fine-tuning; 2:4 semi-structured sparsity is accelerated on Ampere+ GPUs.

What is knowledge distillation and how do you implement it in PyTorch?

Train a small student to mimic a large teacher's softened outputs.

T = 4.0
with torch.no_grad(): t_logits = teacher(x)
s_logits = student(x)
kd = F.kl_div(F.log_softmax(s_logits / T, -1), F.softmax(t_logits / T, -1),
              reduction="batchmean") * T * T
loss = alpha * kd + (1 - alpha) * F.cross_entropy(s_logits, y)

Implement a simple CNN for image classification. How do you compute output sizes?

class SimpleCNN(nn.Module):
    def __init__(self, num_classes=10):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(3, 32, 3, padding=1), nn.BatchNorm2d(32), nn.ReLU(), nn.MaxPool2d(2),
            nn.Conv2d(32, 64, 3, padding=1), nn.BatchNorm2d(64), nn.ReLU(), nn.MaxPool2d(2))
        self.pool = nn.AdaptiveAvgPool2d(1)
        self.fc = nn.Linear(64, num_classes)
    def forward(self, x):                 # x: (N, 3, H, W)
        x = self.pool(self.features(x))   # (N, 64, 1, 1)
        return self.fc(torch.flatten(x, 1))

Output size: floor((W + 2P - D·(K-1) - 1) / S) + 1. AdaptiveAvgPool2d makes the head independent of input resolution. Use bias=False on convs followed by BatchNorm.

Implement a residual block.

class ResBlock(nn.Module):
    def __init__(self, c_in, c_out, stride=1):
        super().__init__()
        self.conv1 = nn.Conv2d(c_in, c_out, 3, stride, 1, bias=False); self.bn1 = nn.BatchNorm2d(c_out)
        self.conv2 = nn.Conv2d(c_out, c_out, 3, 1, 1, bias=False);     self.bn2 = nn.BatchNorm2d(c_out)
        self.short = nn.Identity() if stride == 1 and c_in == c_out else nn.Sequential(
            nn.Conv2d(c_in, c_out, 1, stride, bias=False), nn.BatchNorm2d(c_out))
    def forward(self, x):
        out = F.relu(self.bn1(self.conv1(x)))
        out = self.bn2(self.conv2(out))
        return F.relu(out + self.short(x))

Skip connections give gradients a direct path, enabling very deep networks.

Implement scaled dot-product self-attention / multi-head attention.

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, n_heads, dropout=0.1):
        super().__init__()
        assert d_model % n_heads == 0
        self.h, self.dk = n_heads, d_model // n_heads
        self.qkv = nn.Linear(d_model, 3 * d_model)
        self.out = nn.Linear(d_model, d_model)
        self.drop = nn.Dropout(dropout)
    def forward(self, x, mask=None):                    # x: (B, T, D)
        B, T, D = x.shape
        q, k, v = self.qkv(x).view(B, T, 3, self.h, self.dk).permute(2, 0, 3, 1, 4)
        att = (q @ k.transpose(-2, -1)) / math.sqrt(self.dk)   # (B, h, T, T)
        if mask is not None:
            att = att.masked_fill(mask == 0, float("-inf"))
        att = self.drop(att.softmax(-1))
        y = (att @ v).transpose(1, 2).reshape(B, T, D)
        return self.out(y)

In practice use F.scaled_dot_product_attention(q, k, v, is_causal=True), which dispatches to FlashAttention / memory-efficient kernels. Causal mask: torch.tril(torch.ones(T, T)).

Implement a transformer encoder block (pre-norm).

class Block(nn.Module):
    def __init__(self, d, h, ff=4, p=0.1):
        super().__init__()
        self.ln1, self.ln2 = nn.LayerNorm(d), nn.LayerNorm(d)
        self.attn = MultiHeadAttention(d, h, p)
        self.mlp = nn.Sequential(nn.Linear(d, ff * d), nn.GELU(), nn.Linear(ff * d, d), nn.Dropout(p))
    def forward(self, x, mask=None):
        x = x + self.attn(self.ln1(x), mask)
        return x + self.mlp(self.ln2(x))

Built-ins: nn.TransformerEncoderLayer(d_model, nhead, batch_first=True, norm_first=True), nn.MultiheadAttention (note its key_padding_mask uses True = ignore).

How do you implement positional encodings and embeddings?

class SinusoidalPE(nn.Module):
    def __init__(self, d, max_len=5000):
        super().__init__()
        pos = torch.arange(max_len).unsqueeze(1)
        div = torch.exp(torch.arange(0, d, 2) * (-math.log(10000.0) / d))
        pe = torch.zeros(max_len, d)
        pe[:, 0::2], pe[:, 1::2] = torch.sin(pos * div), torch.cos(pos * div)
        self.register_buffer("pe", pe)
    def forward(self, x): return x + self.pe[: x.size(1)]

nn.Embedding(vocab, d, padding_idx=0) maps token IDs to vectors; learned positional embeddings use another nn.Embedding(max_len, d); modern LLMs use RoPE.

How do you build a simple autoencoder or GAN training step?

Autoencoder: encoder → bottleneck → decoder; loss = MSE/BCE between input and reconstruction. GAN step: (1) update discriminator on real (label 1) and fake.detach() (label 0) with BCEWithLogitsLoss; (2) update generator with the discriminator's output on fake labeled as real. Separate optimizers (Adam, betas=(0.5, 0.999)); detach prevents generator gradients during the D step.

What is the reparameterization trick? How is it used in a VAE?

Gradients can't flow through random sampling. Instead of sampling z ~ N(μ, σ²) directly, sample ε ~ N(0, 1) and compute z = μ + σ·ε, which is differentiable with respect to μ and σ.

mu, logvar = enc(x).chunk(2, dim=-1)
z = mu + torch.exp(0.5 * logvar) * torch.randn_like(mu)
recon = dec(z)
kl = -0.5 * torch.sum(1 + logvar - mu.pow(2) - logvar.exp(), dim=-1).mean()
loss = F.mse_loss(recon, x, reduction="sum") / x.size(0) + kl

torch.distributions provides the same through Normal(mu, std).rsample() (reparameterized) vs .sample() (no gradient), along with log_prob, entropy and kl_divergence. These are also used in RL policy gradients.

What is the KV-cache in autoregressive transformers?

When generating token by token, the keys and values of earlier tokens don't change. Caching them means each new step computes Q, K and V only for the new token and attends over the cached K and V. Without a cache, each step recomputes the whole prefix (quadratic total cost); with it, the per-step cost is linear in context length. The trade-off is memory: 2 × layers × heads × head_dim × seq_len × batch × bytes. Optimizations include MQA/GQA (shared KV heads), paged attention (vLLM), KV quantization and sliding windows.

27. Debugging & Common Pitfalls

Your training loss is NaN. How do you debug it?

  • Check inputs/labels for NaN/inf (torch.isfinite(x).all()) and correct normalization.
  • Lower the learning rate; add warmup and gradient clipping.
  • Numerical issues: log(0), division by zero, softmax + log separately → use log_softmax, BCEWithLogitsLoss, add eps.
  • fp16 overflow → use GradScaler or bf16.
  • torch.autograd.set_detect_anomaly(True) to find the op producing NaN in backward (slow; debug only).
  • Forward hooks to locate the first layer producing NaN.

The loss doesn't decrease. What do you check?

  • Overfit a single small batch first — if it can't reach ~0 loss, there's a bug.
  • Forgot zero_grad(), optimizer.step(), or optimizer created with wrong params (e.g., before replacing the head).
  • Applied softmax before CrossEntropyLoss; wrong target dtype/shape; label/input misalignment after shuffling.
  • Learning rate too high/low (LR range test); bad initialization; dead ReLUs.
  • Frozen parameters accidentally; detach()/.data/numpy conversions breaking the graph.
  • Inspect gradient norms per layer (vanishing/exploding).

List common PyTorch mistakes.

  1. Forgetting model.eval() during validation/inference (or model.train() afterwards).
  2. Not using no_grad/inference_mode in evaluation → memory blow-up.
  3. Accumulating loss instead of loss.item().
  4. Softmax before CrossEntropyLoss; float targets for class indices.
  5. Tensors on different devices; tensor.to(device) without reassigning.
  6. Broadcasting shape bugs ((N,) vs (N,1)).
  7. Using view on non-contiguous tensors.
  8. Layers in plain Python lists (not registered).
  9. Not calling sampler.set_epoch in DDP (same shuffle each epoch).
  10. Same random augmentation seeds across DataLoader workers with NumPy RNG (older versions).
  11. Scheduler stepped at the wrong frequency.
  12. Loading a DDP checkpoint with module. prefixes into a non-DDP model.
  13. Using .data (bypasses autograd safety) instead of detach() / no_grad.

How do you load a checkpoint saved from DDP/torch.compile into a plain model?

Keys are prefixed with module. (DDP) or _orig_mod. (compile). Strip them: {k.removeprefix("module."): v for k, v in sd.items()}, or save model.module.state_dict() / the original module's state dict in the first place.

What causes "Expected all tensors to be on the same device" and "expected scalar type Float but found Double"?

Device mismatch: input, model, targets, or a tensor created inside forward (e.g., torch.zeros(...) without device=x.device) live on different devices — create tensors with device=x.device or register them as buffers. Dtype mismatch: NumPy arrays are float64 by default; convert with .float() or torch.from_numpy(a).float().

How do you detect overfitting and data leakage in a PyTorch pipeline?

Plot train vs validation curves; compare against a simple baseline; check that augmentations/normalization statistics are computed on training data only; ensure no duplicates or same-entity samples across splits; verify the validation transform is deterministic; evaluate on a held-out test set once.

Implement linear regression from scratch using only tensors and autograd.

X = torch.randn(100, 3); true_w = torch.tensor([2., -1., .5])
y = X @ true_w + 0.3 + 0.1 * torch.randn(100)
w = torch.zeros(3, requires_grad=True); b = torch.zeros(1, requires_grad=True)
lr = 0.1
for _ in range(200):
    loss = ((X @ w + b - y) ** 2).mean()
    loss.backward()
    with torch.no_grad():
        w -= lr * w.grad; b -= lr * b.grad
        w.grad.zero_(); b.grad.zero_()

Parameter updates happen inside no_grad so they aren't tracked.

Implement softmax and cross-entropy in a numerically stable way.

def log_softmax(z, dim=-1):
    z = z - z.max(dim=dim, keepdim=True).values      # shift for stability
    return z - z.exp().sum(dim=dim, keepdim=True).log()

def cross_entropy(logits, targets):
    return -log_softmax(logits).gather(1, targets.unsqueeze(1)).mean()

Implement dropout and batch normalization manually.

def dropout(x, p, training):
    if not training or p == 0: return x
    mask = (torch.rand_like(x) > p).float()
    return x * mask / (1 - p)                  # inverted dropout keeps expectation

class MyBatchNorm1d(nn.Module):
    def __init__(self, n, eps=1e-5, momentum=0.1):
        super().__init__()
        self.gamma, self.beta = nn.Parameter(torch.ones(n)), nn.Parameter(torch.zeros(n))
        self.register_buffer("rm", torch.zeros(n)); self.register_buffer("rv", torch.ones(n))
        self.eps, self.m = eps, momentum
    def forward(self, x):
        if self.training:
            mean, var = x.mean(0), x.var(0, unbiased=False)
            with torch.no_grad():
                self.rm.lerp_(mean, self.m); self.rv.lerp_(x.var(0, unbiased=True), self.m)
        else:
            mean, var = self.rm, self.rv
        return self.gamma * (x - mean) / torch.sqrt(var + self.eps) + self.beta

Explain what happens step by step in one training iteration, from data to updated weights.

DataLoader worker reads samples → transforms → collate_fn builds a batch → pinned memory → async copy to GPU → forward pass builds the autograd graph and saves activations → loss computed → backward() traverses the graph in reverse computing VJPs, accumulating .grad (in DDP, gradient buckets all-reduced concurrently) → optional unscale/clip → optimizer.step() updates parameters using its state (momentum/Adam moments) → scheduler updates LR → gradients zeroed → graph freed.

Implement IoU and Non-Maximum Suppression (NMS).

def box_iou(a, b):                       # a: (N,4), b: (M,4) as x1,y1,x2,y2
    area_a = (a[:, 2] - a[:, 0]) * (a[:, 3] - a[:, 1])
    area_b = (b[:, 2] - b[:, 0]) * (b[:, 3] - b[:, 1])
    lt = torch.max(a[:, None, :2], b[None, :, :2])
    rb = torch.min(a[:, None, 2:], b[None, :, 2:])
    inter = (rb - lt).clamp(min=0).prod(-1)
    return inter / (area_a[:, None] + area_b[None, :] - inter)

def nms(boxes, scores, thr=0.5):
    order, keep = scores.argsort(descending=True), []
    while order.numel() > 0:
        i = order[0]; keep.append(i.item())
        if order.numel() == 1: break
        ious = box_iou(boxes[i:i+1], boxes[order[1:]])[0]
        order = order[1:][ious <= thr]
    return torch.tensor(keep)

def clip_loss(img_emb, txt_emb, temperature=0.07):
    img = F.normalize(img_emb, dim=-1); txt = F.normalize(txt_emb, dim=-1)
    logits = img @ txt.T / temperature                 # (B, B) similarity matrix
    targets = torch.arange(len(img), device=img.device)  # matching pairs on diagonal
    return (F.cross_entropy(logits, targets) + F.cross_entropy(logits.T, targets)) / 2

The other samples in the batch serve as negatives, so larger batches help. SimCLR applies the same idea to two augmented views of each image.

Implement text generation with temperature, top-k and top-p sampling.

@torch.inference_mode()
def generate(model, ids, max_new=50, temperature=0.8, top_k=50, top_p=0.9, eos_id=None):
    for _ in range(max_new):
        logits = model(ids)[:, -1, :] / max(temperature, 1e-5)
        if top_k:
            kth = torch.topk(logits, top_k).values[:, -1, None]
            logits = logits.masked_fill(logits < kth, float("-inf"))
        if top_p < 1.0:
            sorted_logits, idx = logits.sort(descending=True)
            cum = sorted_logits.softmax(-1).cumsum(-1)
            remove = cum - sorted_logits.softmax(-1) > top_p      # keep first token past p
            sorted_logits[remove] = float("-inf")
            logits = torch.full_like(logits, float("-inf")).scatter(-1, idx, sorted_logits)
        next_id = torch.multinomial(logits.softmax(-1), 1)
        ids = torch.cat([ids, next_id], dim=1)
        if eos_id is not None and (next_id == eos_id).all(): break
    return ids

Temperature below 1 sharpens the distribution and above 1 flattens it. Greedy decoding uses argmax; beam search keeps the k best sequences. Real implementations use a KV-cache instead of re-running the full prefix.

Implement k-means clustering using only PyTorch tensors.

def kmeans(x, k, iters=50):
    c = x[torch.randperm(len(x))[:k]].clone()
    for _ in range(iters):
        assign = torch.cdist(x, c).argmin(1)             # (N,)
        new_c = torch.zeros_like(c).index_add_(0, assign, x)
        counts = torch.bincount(assign, minlength=k).unsqueeze(1)
        new_c = torch.where(counts > 0, new_c / counts.clamp(min=1), c)   # keep empty clusters
        if torch.allclose(new_c, c): break
        c = new_c
    return c, assign
